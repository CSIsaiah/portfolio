Why I built it

Security concepts.
Working together.

I built SecurePass+ for my Data Security final assignment to put password storage, authentication, and encryption concepts into a working desktop application.

I developed the interface and the supporting Python modules for the master-password check, vault storage, and one-time code generation. Keeping those responsibilities separate helped me connect the user’s actions to the underlying security logic.

Individual coursework. The screenshots on this page come from my submitted assignment and use example entries. This is a desktop application; the portfolio presents its interface and implementation.

What the app does

Small interface.
Several connected systems.

Local storage · Desktop application
01

Master-password login

First-time setup creates a master password. Later launches require it before the GUI opens the vault.

02

An encrypted local vault

Saved entries are encrypted with Fernet using a key derived from the master password, then stored in a local file.

03

Save, view, and delete

Keep a website name, username, and password together. View saved entries or select an entry to delete with confirmation.

04

Time-based one-time codes

Generate a TOTP code from a shared secret using PyOTP. This is a separate code-generation tool; vault login uses the master password.

Behind the interface

From sign-in
to saved data.

  1. 01

    Check the login

    The GUI compares a SHA-256 hash of the entered master password with the stored hash.

  2. 02

    Derive the vault key

    PBKDF2-HMAC-SHA256 derives a key from the master password for Fernet encryption and decryption.

  3. 03

    Persist the entries

    Fernet encrypts the vault contents before saving them locally. The same master password opens the saved vault in a later session.

What I learned

The details
connect the whole.

This project helped me understand how password verification, key derivation, encrypted persistence, and a desktop interface fit together.

It also showed me why edge cases matter: missing files, incorrect passwords, invalid OTP secrets, and changes to the master password affect both the user experience and the stored data.

Reflection and next steps

Completed coursework.
More to strengthen.

SecurePass+ is an educational prototype. A production password manager would need further security review and testing.

The current master-password change action updates the login hash without re-encrypting the existing vault. Improving that flow, using a unique per-vault salt and stronger password-hash storage, and adding backup and restore are next steps.
